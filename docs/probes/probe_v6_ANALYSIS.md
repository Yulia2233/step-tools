# v6 STEPIR 诊断：codex 逆向 16 个零件后，还该优化什么（2026-11-05）

## 怎么做的

- 16 个零件：12 个真实 ABC 件，按旧 IR 下教师的结果分层（旧 ≥0.99 的 6 件、旧 0 分 5 件、旧 0.5–0.99 的 1 件）；另 4 个 codex 自由曲面件（扫掠 2、放样 1、样条回转 1，构造代码已知）。
- 每件给 codex（gpt-6.1-sol）v6 IR（`--augment --fit`）和按需查询工具，任务是重建到 riou ≥ 0.99。**同时要求边做边写 `decisions.md`**：每轮依据了 IR 的哪些事实、在 IR 之外量了什么、为什么。结束时写 `report.json`：缺了什么、哪里误导、最想改的一处。
- 我们自己复评 `rebuild.py` 并扫描是否读取目标。另从 codex 事件流统计它在 IR 之外调了哪些检查接口。
- 另对 500 个真实 ABC 件统计 v6 IR 的 token 构成和缺失信息。
- 3 个案例第一次因 codex 端点 `502 Bad Gateway` 中断，已重跑；abc_00000043（7 个实体）写本文时仍在重跑。

## 结果

| 零件 | 旧 IR | v6 IR |
|---|---|---|
| 单实体 11 件 | — | **10 件 ≥ 0.996**；abc_00000477 从 0.966 升到 0.9999；abc_00000064 从 0.996 降到 0.20（见下） |
| 多实体 4 件（320/933/491/520） | 0 | 0 |

**多实体是旧"218 难件"的真相**：教师在旧 IR 下得 0 的 218 件里，**203 件是多实体 STEP**（多个实体，常互相重叠），成功的 251 件**全部是单实体**。500 件真实池里 41%（203 件）是多实体。之前把它们当作"几何太难"是误判：重建一个单实体去比多实体目标，得分必然是 0。

abc_00000064 的下降只有一次运行，不足以说明退化：旧运行用圆形截面放样做出 0.996；这次把它当成"扭转叶片"，**没有利用 IR 里对这些样条面给出的 `revolve` 行**，只用了 6 轮就停了。

## 需要优化的地方（按收益排序）

### 1. 实体信息（影响最大，改动最小）
- **问题**：表头没有实体数；13/15 份报告把"实体数"列为缺失，16 次运行里有 12 次专门去量。多实体件里，各面属于哪个实体也不知道；棱柱配对会跨实体把两个实体的底面配成一对（abc_00000320）。
- **改法**：表头加 `solids` 表（数量、各自体积/包围盒、是否互相重叠及并集体积）；每个面加实体号 `b`；棱柱只在同一实体内配对。
- **更上游的决定（需要你定）**：多实体 STEP 要么从训练/评测数据中过滤掉，要么让任务和评分支持多实体输出；否则 41% 的真实件注定 0 分。

### 2. 修掉会误导的输出（是 bug，必须修）
- **按需查询的子午轮廓算错**：圆锥把母线长度当成轴向长度，半径用 `tan` 而不是 `sin`；坐标是相对轴点的局部值，不标注。4 次运行发现后弃用。例：45° 倒角锥，母线长 1.1136，代码给半径增量 1.114，正确为 0.787（codex 量出的 4.7625 与之吻合）。
  改法：`z = v·cosα`、`r = R + v·sinα`，输出绝对坐标、真实端点。
- **圆锥有两套约定**：v6 识别出的锥是"p 在小端、d 指向半径增大"，但原生解析锥仍是 SDK 的"参考半径 + 可为负的 v"。改法：像 v5 处理圆柱那样把所有锥统一规范化。
- **回转曲面、拉伸曲面被写成 `OTHER`**（500 件里 22 件有）：丢掉了轴和母线；`evidence` 查询还对它给出"决定性的螺旋运动"（螺距 957）的错误结论。改法：写成 `REV`/`EXT` 记录，带轴或方向和母线；病态拟合不报"决定性"。
- **侧面是螺旋面的两个圆形端面被标成棱柱**（abc_00000520）。改法：棱柱需要侧面确实是端面边的直线扫掠。

### 3. 自由曲面缺"能直接建模的参数"（最耗回合）
- 现状只给"这组面是放样/扫掠"，codex 还要自己查控制网、切截面：放样件 x033 求值了 81 个截面，放样件 064 失败，扫掠件 x003 试了 3 条轨道，螺纹件 775 自己从控制网解螺距。
- **改法**：对每个放样/扫掠组给出构造参数：
  - 扫掠：轨道曲线（中心线极点）、截面线框、截面是否沿轨道变化（x018 的截面在中点收缩到 0，"全等"判断取错了方向）；
  - 放样：若干站位处闭合、有序的截面；
  - 螺纹/螺旋：轴、螺距、旋向、牙型。

  紧凑摘要放第一层，完整曲线放按需查询。这与 MIRAGE-CAD（arXiv 2608.28669）"用显式构造计划作中介"的结论一致：计划与参考构造的一致度能预测执行成败。

### 4. 倒角做成"操作级分组"
- 500 件里 5659 条倒角行只对应 904 种（类型、半径），平均 6 条是同一次 `fillet_rsolid`。codex 想要"一组相连的圆角 + 明确排除的那条边"（abc_00000477）。
- 支撑面有时是另一块圆角片（abc_00000491），没法直接当选边依据。改法：沿圆角链走到原始面。
- 样条曲面上的等半径圆角被标成放样/自由曲面（abc_00000314）。改法：加"滚球圆角"判据（与两面相切且到两面距离恒定）。
- 改法汇总：一行一个倒角操作（种类、半径、边的支撑面对列表、链连通性）。也减 token。这与 Pointer-CAD（2603.04337）、FutureCAD（2603.11831）把"实体选择"作为一等对象的做法一致。

### 5. token（次要）
- 平面记录占 32%（其中边界环 17%），圆柱占 15.5%；**78% 的圆柱记录在同一零件内重复**（同半径、同方向、同长度），是孔阵列。
- 改法：阵列压缩，例如 `{"pattern":{"of":id,"n":6,"step":[...]}}` 或环形阵列。
- 全精度：3 份报告嫌 4 位小数不够贴合，放到按需查询即可，不必改第一层。

## 局限
- 每个零件只跑了一次，单次结果方差大（064 的例子）。上面的排序依据的是"多份报告提到 + 我们能独立复核"的问题：实体数、圆锥子午轮廓的数值都已复核。
- codex 的自述有偏差，所以结论尽量用事件流里的实际调用次数佐证。
- 第一次运行的 502 来自 codex 配置的中转端点（明文 HTTP 的 IP 地址），与本实验无关，但这个端点值得你确认是否符合预期。

数据：`cases/<id>/{target.ir.jsonl, decisions.md, report.json, rebuild.py, verdict.json, events.jsonl}`；首次 502 中断的原始输出在 `failed_502/`。
