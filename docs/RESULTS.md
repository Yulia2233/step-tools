# STEPIR 计算几何优化：结果、证据与局限（2026-11-05）

分支 `autoresearch/stepir-geom-1105e`（仓库 `stepir_geom/`，与主仓库的 `research/` 互相独立）。被测代码是本目录；基准与评分器在 `../bench/`。
**主仓库的 `research/tools/stepir.py` 没有被改动**——新 IR 的格式（派生行、合并后的面号、被隐含面）与旧版不兼容，采用前需要决定训练数据是否重建。

## 一句话结论

在**从未参与调参的 120 个真实 ABC 零件**上，对同一零件做"拆面 / 转 NURBS / 两者叠加"后：

| | 原始 stepir | 本版本 |
|---|---|---|
| 同一零件在不同表示下 LLM 看到的 IR 是否一致（稳定性） | 0.193 | **0.958** |
| 同一曲面被切开的碎片是否并回一个面（合并 F1） | 0.018 | **0.992** |
| NURBS 里的平面/圆柱/圆锥/球/环面认回解析曲面（召回 / 特异度） | 0 / 1.000 | **0.974 / 1.000** |
| IR token（原件 / 拆面 / 转 NURBS / 两者叠加） | 6635 / 12161 / 14759 / 26449 | **5418 / 5927 / 5081 / 5840** |

即：IR 长度不再随建模器的表示方式膨胀（最坏 4 倍），原件也短了约 18%。

## 各能力的成功率（合成基准：260 件，dev 族；括号为 held-out 族）

总分 `SCORE` 0.855（基线）→ 0.926（0.927）。分项：

| 能力 | 基线 | 现在 | 说明 |
|---|---|---|---|
| 曲面识别（解析面召回；自由曲面不被误判） | 0.50 | 0.995 | 召回 0.97、特异度 1.00 |
| 同曲面连通面合并（成对 F1） | 0.004 | 0.972 | 剩余多为 OCC 拆分时被重新逼近的样条碎片 |
| 稳定性 | 0.124 | 0.978 | |
| 操作来源（回转/螺旋/放样/扫掠/…） | 0.586 | 0.820 | 回转 1.00、螺旋 0.96、扭转 0.90、扫掠 0.91、放样 0.71 |
| 倒角/圆角：标出面 ∧ 圆滑的两个面 ∧ 半径 | 0.257 | 0.824 | 见下"局限" |

放样与扫掠的区分：刚体不变量检验——扫掠面沿轨道的各条等参线是同一轮廓的刚体拷贝，距离矩阵不变（扫掠 89% 低于 1e-3，放样 0% 低于 1e-3）。

## 方法（按信息分层，见 `DESIGN_TIERS.md`）

1. **曲面识别**（`geomnorm.py`）：精确 D1 采样（点+外法向）→ 平面（SVD）→ 球（法线交点）→ 回转面（法线与轴相交的 6×6 线性方程，再在 (z,ρ) 平面看子午线是常数/直线/圆）。
2. **边识别**：B 样条边认回直线、圆弧、整圆，平面环才能重新编码成 L/A/C，棱柱压缩才能重新生效。
3. **合并**：解析面按载体参数、样条面按"沿共享边法向与曲率（G2）连续"；组内共享边抵消、剩余有向边串成闭环；合并共线线段与同圆弧。合并后的范围在所有成员上重新实测。
4. **倒角圆角**（`blends.py`）：在识别、合并后的面上找（G1 相切且截面圆弧 <170° / 夹在两个平面之间 / 与共轴圆柱和垂直平面相邻的圆锥）；被 IR 隐含的支撑面在行内直接写载体。
5. **操作来源**：cadfit 运动学残差阈值 3e-4（真实扫掠 ~1e-9，放样的扭转 ≥7e-4）；非刚体面再按截面全等分放样/扫掠。
6. **信息分层**：无证据的派生行（对圆柱/平面的"既可拉伸又可回转"、可重算的子午轮廓）从基础 IR 剪掉，评分不变、token 少 15%；样条完整控制网、cadfit 证据、相邻关系放进 `stepir_query.py` 按需查询。

## 过拟合审计（用户要求：不要过拟合）

- 合成基准来自**两个生成器**（另一会话的 200 件程序化零件 + codex 生成的 60 件曲线轨道扫掠/放样/样条回转），风格单一、全是 OCC 精确几何。
- 因此用三类**独立证据**核对：
  1. 120 个真实 ABC 件做拆面/转 NURBS 扰动的盲测（上表）：结果与合成基准一致。
  2. 150 个真实、带文件名标注的件（`_fillet_N`/`_chamfer_N`，与评测集 ID 不相交）检验倒角圆角规则。**这次检验推翻了我之前的两条规则**：对称倒角假设、锥面相对尺寸 0.2 都是照着生成器调的，会漏掉真实倒角。已按真实分布改为 0.3 并恢复不等距倒角的退路，**合成基准分数因此主动下降 0.013**（保留）。
  3. 曲面识别容差灵敏度（真实件）：放大 10 倍才开始误判，100 倍崩溃，缩小 10 倍召回略升；当前值离失效点有 10 倍余量，不是尖峰。
- 真实件上还发现并修复一个只有真实几何才暴露的 bug（双锥的两个半锥因镜像顶点候选被误并）。

## 局限（必须知道）

- **倒角圆角在真实件上并不比 SDK 原有提示更准**：倒角件召回 24/75（旧 26/75）、圆角件 47/75（旧 49/75）。本版本的价值是**对 NURBS/拆面表示保持不变**和**支撑面内联**，不是更高的检出率。
- 合成基准里的标签歧义**没有去迎合**：沉头孔锥面≈倒角、草图圆角≈fillet、两个全等截面的线性放样≈拉伸、截面同形平移的 gordon≈扫掠。这些在评分里表现为"误报/错断言"，是真值按代码计算的固有歧义。
- 放样/扫掠的 `sweep_tol=2.5e-3` 来自 OCC 扫掠逼近精度，别的建模器的近似误差可能不同；它给出的是假设性标签，不是证明。
- 补充的 60 件由 codex 生成，只验证了"单个有效实体 + 含自由曲面 + 不读 STEP"，4 件重建体积与 STEP 不一致被跳过；拆面变体有 4 件因体积偏差被剔除。
- 第三层（按需查询）**没有在 agent 轨迹里验证过**是否减少错误和回合数，只验证了取得回来。
- 评分器共修正过 4 次（均在记录对应实验之前，已写入 `.autoresearch/notes.md`）：支撑面须可解析、圆锥顶点比较、变体合理性检查、支撑组可吸收同曲面邻面。另有一处只在**真实件评测副本**里改了（"原本就同曲面"的豁免扩大到整个连通分量），主评分器未改，所以主基准的合并分数对"原本就有一串共面小面"的零件略偏严。真实件脚本在 `../stepir_geom_gen/real_eval/`。
- 一轮完整评测约 6–10 分钟。

## v6.1（2026-11-06）：按 codex 诊断修正 2、3、4 项

依据：`docs/probes/probe_v6_ANALYSIS.md`（codex 用 v6 IR 逆向 16 个零件的决策记录）。多实体零件已从数据中过滤（500 件 ABC 池中单实体 297、多实体 203）。

**第 2 项：会误导的输出**
- 所有圆锥统一一种写法（`p` 在小端、`d` 指向半径增大、`v=[0, 母线长]`）：89 个圆锥面核对，最大相对半径误差 3.6e-4。
- 按需查询的子午轮廓改正：轴向 `v·cosα`、半径 `R + v·sinα`，环面/球给出圆弧端点，`z` 注明从 `point` 沿 `dir` 量起；相邻段首尾相接。
- 回转曲面/拉伸曲面写成 `REV`/`EXT`，带精确母线：回转面写成子午平面内的 (z, r) 极点（x053 与构造代码逐项一致），周期样条标 `periodic`；对应的操作行直接取自载体，不再拟合（不再出现"螺距 957 的螺旋"）。
- 棱柱只在连接两底面的面都是沿法向的直纹面时成立：基准 77 件中 148 个棱柱去掉 22 个误判（Gordon 蒙皮、横穿的圆柱、球面）。

**第 3 项：自由曲面的构造参数**
- 扫掠：`rail`（13 个站位处截面面积质心，沿轨道依次）、`profile`（起始截面：圆或多边形/周期样条，含局部坐标系）、`frame`（`frenet`/`fixed`，按剖面方向随轨道的转动判定；18 例中 16 例正确，2 例错的标了 `?`）。
- 放样：`sections`（同一层内按控制点数等距取截面；首尾相接的多层面——直纹放样、分段放样——各层边界就是原始截面；拆面无法分层时用平行平面截取兜底；最多 8 个）。
- 检验（只用这些参数，用 OCC 重新放样/扫掠，量目标面到重建面的最大距离 / 对角线）：放样 61 条中 57 条在 2% 内（40 条在 0.5% 内）；扫掠 17 条中 14 条在 2% 内（中位 0.66%）。
- 未解决：被布尔运算截掉一部分的放样（截面不闭合，case-241）；Gordon 片体被标成扫掠且无剖面（case-001…005）；Frenet 扫掠穿过拐点时生成的管子在拐点处缩成 0（x018、case-217，这是生成的零件本身的问题）。
- 代价：自由曲面件上构造参数占 IR 的 11%（每行中位 222 token）。

**第 4 项：倒角圆角按"一次操作"分组**
- 输出改为一行一个操作：`{"derived":"fillet","r":...,"faces":[...],"between":[[A,B],...],"corners":[...]}`、`{"derived":"chamfer","d":...,...}`。
- 新增：样条曲面上的等半径滚球圆角（至少一个支撑面是解析面——否则可能是扫掠/放样剖面上的圆角，几何上无法区分）；球面/环面角片并入圆角链；支撑面优先取原始面，只能落在另一块圆角片上时标 `on_blend`（需先做那一块）；倒角给出两侧退距 `d`，退距超过对角线 8% 的标 `uncertain`（真实件中倒角中位 1.3%，误检中位 3.9%，两者重叠，不硬删）。
- 结果：合成基准 SCORE 0.9261 → 0.9295（倒角 0.824 → 0.840，来源 0.819 → 0.824），token 比 0.909 → 0.889。真实带标签零件的召回不变（倒角件 24/75，圆角件 47/75）。

**真实件复测（只含单实体）**：开发集 / 盲测集 稳定性 0.956 / 0.960，合并 1.00 / 0.991，解析面召回 0.979 / 0.990，特异度 1.0。

- 周向范围超过 360° 时 `span` 封顶 360，另给 `wraps`。
- 表头增加 `solids`（实体数）。
- 子午轮廓沿路径首尾串接，断开处显式标 `gap`。
- 空列表一律省略。

## v6.2.2（2026-11-07）：适配 SimpleCADAPI 2.2.7

2.2.7 改用随安装包编译的 C++ 几何内核（内置 OpenCASCADE 7.9.3），不再依赖 OCP；`inspect.brep` 返回的面、边是 SDK 自己的内核对象，OCP 函数不认，旧版直接报类型错误。新增 `cand/sdk_ocp.py`：把整个模型按 OpenCASCADE 二进制格式一次转成 OCP，再用与 SDK 相同的 `TopExp.MapShapes` 重新编号，面号、边号与 SDK 一致、相邻面共享边不被拆开。2.2.7 下需要 `pip install "simplecadapi[verify]"`（提供 OCP）。

2.2.5 下输出逐字节不变。2.2.7 下约 1% 的行有微小差异，只在运动学拟合的派生行（回转轴参考点、螺距末位、近似拉伸方向的符号，个别扫掠/放样临界判定）：原因不是几何不同，而是 2.2.5 里 SDK 与 STEPIR 共用同一批形体对象，SDK 先前生成的三角网格留在面上、改变了采样点；2.2.7 走独立副本不受影响。让 2.2.5 也用独立副本后，与 2.2.7 的输出逐行一致。

## v6.3（2026-11-08）：刻字 / 标志 / 样条轮廓拉伸，以及 `query face` 修复

**起因**：v6.2.2 下刻字、标志、齿形这类"样条轮廓沿法向拉伸"的件，侧壁是一片片 B 样条记录（每片约 600 字符，带三维边界环），平面环里的样条段只有 `["S",次数,终点,形心]`，模型只看 IR 画不出精确字形；刻在曲面上的字完全看不到。另外 STEP 读入后载体常被包在 `Geom_RectangularTrimmedSurface` 里，回转面/拉伸面被认成 `OTHER`，`query face` 调 `NbUPoles` 直接报错（data-1108 的 cad-code 逆向里 6 件碰到，5 件失败）。

**改动**（`cand/`，分支 stepir-v6.3，最终 338fb63）：
- `sdk_ocp.surface()` 去掉裁剪包装，回转/拉伸面恢复为 `REV`/`EXT`；`stepir_query.face` 对任何载体给精确描述（B 样条网、回转/拉伸的轴与母线、偏置、其余转 B 样条标 `converted`），被省略的侧壁也能查。
- 直纹拉伸 B 样条面（一个方向 1 次、两排极点互为平移、权重相同）认作 `EXT`，带精确母线，且优先于容差内拟合出的圆锥/球/环面；母线落在垂直于 `d` 的平面内时写成 2D `uv`（坐标系 `p, x, y=d×x`，节点归一到 [0,1]）。
- 环棱柱：两个平行平面上点集相同的环，若每段都有一面直壁（平面/圆柱/EXT；平面壁须是纯直线带）连接且直壁只碰这两个环、只在两个高度之间，则侧壁省略；持有方写 `"prism":[[环号, 对方id, dz]]`，对方的环写 `{"same":[id,环号]}`。外环且 dz<0 或内环且 dz>0 为加料，否则为切除。
- 平面环样条段在侧壁被省略的环里、或不比短式长（≤4 极点的 Bezier）时写成精确的 `["B",次数,[极点],{"k","m","w"}]`。
- `relief` 派生行（emboss/engrave/imprint）与表头 `relief:{faces,types}`；skill 的 stepeval 据此允许重建不做刻字面（`relief_omitted`）。
- 旧棱柱压缩的 bug：与底边共面但带圆弧或孔的面曾被当作侧面省略，现要求是纯直线带（由新核验工具发现）。
- `tools/verify_implied.py`：对每个被省略的面取网格节点，检查它落在 IR 打印出的某个扫掠上；`tools/cmp_run.py`/`cmp_tokens.py`：两版在真实件上的对比。

**结果**：
- 例：DragonHelmet 标志件 26.7K → 6.2K 字符，89 个侧壁省略，核验偏差 ≤ 0.0024 mm；键帽 "Ctrl" 贴印给 `relief imprint`；按渲染抽查 Hudson、"…com"、185°C、APPRO、WENGER 等刻字件的 relief 判定正确，外壳凸耳的误报已去掉。
- 104 个真实件（`tools/cmp_parts.txt`；3 件新旧两版都超时或单边超时，对比 101 件）：Qwen token 5.83M → 4.60M（−21%，中位每件 −8%，p10 每件 −56%）；被省略的面 460 → 7397；核验 7674/7674 通过；31 件给出 relief；3 件变长 >3%（样条段由短式改为精确式、或回转面恢复后带母线）。
- 合成基准：SCORE 0.9301 → 0.9267（held-out 0.9303 → 0.9291），token 比 0.892 → 0.806，0 错误。下降全部在"样条拉伸"来源（0.606 → 0.375）：这些侧壁被环棱柱省略，评分器把没有记录的面映射为 -1、不给来源分；把省略面补进 `op` 行也不能恢复（已撤回）。其余分项持平。
- `query face` 在 data-1108 那 7 个出错件上对 REV、EXT 与被省略侧壁均正常返回。

**兼容性**：面号分配不变，但部分面类型（BSPL/CONE → EXT，OTHER → REV/EXT）和被省略的面变了；用 v6.2.x IR 生成的数据与 v6.3 的 `query` 输出可能对不上，混用前要重建 IR。
